# ACP2E-4799: GraphQL query requisition_lists returns incorrect total_count with pagination

The ACP2E-4799 patch fixes the issue where the requisition_lists GraphQL query returned an incorrect total_count value that reflected only the number of items on the current page instead of the total number of requisition list entities matching the query criteria. This patch is available when the [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.82 is installed. The patch ID is ACP2E-4799. Please note that this issue is scheduled to be fixed in Adobe Commerce B2B 1.5.4.

## Affected products and versions

**The patch is created for Adobe Commerce version:**

* Adobe Commerce (all deployment methods) B2B 1.5.2-p4

**Compatible with Adobe Commerce versions:**

* Adobe Commerce (all deployment methods) B2B >=1.5.0 <1.5.3

>[!NOTE]
>
>The patch might become applicable to other versions with new [!DNL Quality Patches Tool] releases. To check if the patch is compatible with your Adobe Commerce version, update the `magento/quality-patches` package to the latest version and check the compatibility on the [[!DNL Quality Patches Tool]: Search for patches page](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Use the patch ID as a search keyword to locate the patch.

## Issue

Issue where the requisition_lists GraphQL query returned an incorrect total_count value that reflected only the number of items on the current page instead of the total number of requisition list entities matching the query criteria.

<u>Prerequisites</u>:

Adobe Commerce [!DNL B2B] module with Requisition List enabled.

<u>Steps to reproduce</u>:

1. In the Admin, go to Stores > Settings > Configuration. In the left panel under General, choose [!DNL B2B] Features. Set Enable Requisition List to Yes and click Save Config.
1. Sign in to the storefront as the customer. Choose My Requisition Lists and create six requisition lists for the same customer. Ensure that each list name contains ABC so it also matches the filtered query.
1. Run the following GraphQL query with pageSize set to 2 and currentPage set to 1:

   ```
   query {
     customer {
           requisition_lists(
           pageSize: 2
           currentPage: 1
       ){
               items {
                   uid
                   name
               }
               total_count
               page_info {
                   current_page
                   page_size
                   total_pages
               }
           }
       }
   }
   ```

1. Run this GraphQL query:

   ```
   query {
     customer {
           requisition_lists(
           filter: \{ name: { match: "%ABC%" } }
           pageSize: 2
           currentPage: 1    ){
               items {
                   uid
                   name
               }            total_count
               page_info {
                   current_page
                   page_size
                   total_pages
               }
           }
       }
   }
   ```

<u>Expected results</u>:

1. The requisition_lists query returns total_count equal to the total number of requisition lists owned by the customer, independent of pageSize and currentPage.
1. The pagination data remains consistent with the full matching result set.

<u>Actual results</u>:

1. total_count returns only the number of items in the current page, such as 2 instead of 6.
