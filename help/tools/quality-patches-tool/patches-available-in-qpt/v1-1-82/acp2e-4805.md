# ACP2E-4805: Checkout requests slow down for configurable products when the first salable child appears later in the list

The ACP2E-4805 patch fixes the issue where checkout requests, such as totals-information and estimate-shipping-methods, experience significant performance degradation for configurable products with many child products when the first salable child appears later in the list. This patch is available when the [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.82 is installed. The patch ID is ACP2E-4805. Please note that this issue is scheduled to be fixed in Adobe Commerce 2.4.10.

## Affected products and versions

**The patch is created for Adobe Commerce version:**

* Adobe Commerce (all deployment methods) 2.4.8-p4

**Compatible with Adobe Commerce versions:**

* Adobe Commerce (all deployment methods) 2.4.8 - 2.4.8-p5

>[!NOTE]
>
>The patch might become applicable to other versions with new [!DNL Quality Patches Tool] releases. To check if the patch is compatible with your Adobe Commerce version, update the `magento/quality-patches` package to the latest version and check the compatibility on the [[!DNL Quality Patches Tool]: Search for patches page](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Use the patch ID as a search keyword to locate the patch.

## Issue

Issue where checkout requests, such as totals-information and estimate-shipping-methods, experience significant performance degradation for configurable products with many child products when the first salable child appears later in the list.

<u>Prerequisites</u>:

Inventory Management (MSI) is enabled.

<u>Steps to reproduce</u>:

1. Create a configurable product with 600 child products.
1. Disable the first 400 child products by entity_id in ascending order.
1. Add the configurable product to the cart 3 times with different option selections.
1. Open the cart page and observe the response time for the totals-information request.
1. Enable the first child product by entity_id in ascending order.
1. Open the cart page again and observe the response time for the totals-information request.
1. Compare the response times when an early child product is salable versus when the first salable child appears much later in the child product list.

<u>Expected results</u>:

1. All totals-information requests have similar response times regardless of which child product is the first salable one.

<u>Actual results</u>:

1. There is an observable response time change depending on the position of the first salable child.
