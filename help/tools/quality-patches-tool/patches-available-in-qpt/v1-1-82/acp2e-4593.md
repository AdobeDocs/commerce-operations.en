# ACP2E-4593: Wrong Website Restriction CMS page served on the secondary website in multi-website storefronts

The ACP2E-4593 patch fixes the issue where when, in multi-website setups, the Website Restriction landing page cache key was not scoped per website, causing the wrong CMS page to be be served on the secondary website storefront. This patch is available when the [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.82 is installed. The patch ID is ACP2E-4593. Please note that this issue is scheduled to be fixed in Adobe Commerce 2.4.10.

## Affected products and versions

**The patch is created for Adobe Commerce version:**

* Adobe Commerce (all deployment methods) 2.4.5-p15

**Compatible with Adobe Commerce versions:**

* Adobe Commerce (all deployment methods) 2.4.5 - 2.4.9

>[!NOTE]
>
>The patch might become applicable to other versions with new [!DNL Quality Patches Tool] releases. To check if the patch is compatible with your Adobe Commerce version, update the `magento/quality-patches` package to the latest version and check the compatibility on the [[!DNL Quality Patches Tool]: Search for patches page](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Use the patch ID as a search keyword to locate the patch.

## Issue

Issue where when, in multi-website setups, the Website Restriction landing page cache key was not scoped per website, causing the wrong CMS page to be be served on the secondary website storefront.

<u>Prerequisites</u>:

1. Inventory is installed.

<u>Steps to reproduce</u>:

1. Create two websites.
1. Create two CMS pages, add some different text per page to the Content section, and assign each page to a different website.
1. Enable website restrictions and configure a landing page restricted to its corresponding website.
1. Ensure that caching is enabled.
1. Open the storefront for the first website and verify the displayed landing page content.
1. Open the storefront for the second website and observe that it still displays the landing page content from the first website.

<u>Expected results</u>:

Each website should display its respective CMS page correctly on the storefront.

<u>Actual results</u>:

Both websites display the same CMS page, which is the page that was accessed first.
