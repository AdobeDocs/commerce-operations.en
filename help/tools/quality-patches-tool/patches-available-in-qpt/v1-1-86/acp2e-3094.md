# ACP2E-3094: Viewing or editing [!UICONTROL Category Permissions] for category with many permissions causes unresponsive browser

The ACP2E-3094 patch fixes the issue where viewing or editing Category Permissions for a category with many permissions can cause the browser to become unresponsive. This patch is available when the [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.86 is installed. The patch ID is ACP2E-3094. Please note that this issue is scheduled to be fixed in Adobe Commerce 2.4.8.

## Affected products and versions

**The patch is created for Adobe Commerce version:**

* Adobe Commerce (all deployment methods) 2.4.7-p10

**Compatible with Adobe Commerce versions:**

* Adobe Commerce (all deployment methods) 2.4.5 - 2.4.7-p10

>[!NOTE]
>
>The patch might become applicable to other versions with new [!DNL Quality Patches Tool] releases. To check if the patch is compatible with your Adobe Commerce version, update the `magento/quality-patches` package to the latest version and check the compatibility on the [[!DNL Quality Patches Tool]: Search for patches page](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Use the patch ID as a search keyword to locate the patch.

## Issue

When you view or edit **[!UICONTROL Category Permissions]** for a category with many permissions the browser can become unresponsive.

<u>Prerequisites</u>:

Adobe Commerce with **[!UICONTROL Category Permissions]** enabled.

<u>Steps to reproduce</u>:

1. In the Admin panel, go to **[!UICONTROL Stores]** > **[!UICONTROL Settings]** > **[!UICONTROL Configuration]** > **[!UICONTROL Catalog]** > **[!UICONTROL Catalog]**, expand **[!UICONTROL Category Permissions]**, set **[!UICONTROL Enable]** to **[!UICONTROL Yes]**, and click **[!UICONTROL Save Config]**.
1. Make sure that the store has a large number of customer groups, for example 20,000, and that a category, for example Default Category, has a permission for each of them.
1. Go to **[!UICONTROL Catalog]** > **[!UICONTROL Categories]**, select that category, and expand **[!UICONTROL Category Permissions]**.
1. Click New Permission.

<u>Expected results</u>:

1. The **[!UICONTROL Category Permissions]** section opens with the existing permissions split into pages, and the browser stays responsive.
1. Clicking **[!UICONTROL Add Permission], the new name of the **[!UICONTROL New Permission]** button, adds a new permission row.

<u>Actual results</u>:

1. The browser stops responding while the Category Permissions section loads or after New Permission is clicked, and the page can crash with an Out of Memory error.
