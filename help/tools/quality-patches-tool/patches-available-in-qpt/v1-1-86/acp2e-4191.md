# ACP2E-4191: REST API requests enter infinite loop when EAV types and attributes cache disabled

The ACP2E-4191 patch fixes the issue where certain REST API requests enter an infinite loop when the EAV types and attributes cache is disabled. This patch is available when the [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.86 is installed. The patch ID is ACP2E-4191. Please note that this issue is scheduled to be fixed in Adobe Commerce 2.4.9.

## Affected products and versions

**The patch is created for Adobe Commerce version:**

* Adobe Commerce (all deployment methods) 2.4.7-p9, 2.4.8-p2

**Compatible with Adobe Commerce versions:**

* Adobe Commerce (all deployment methods) 2.4.5 - 2.4.8-p5

>[!NOTE]
>
>The patch might become applicable to other versions with new [!DNL Quality Patches Tool] releases. To check if the patch is compatible with your Adobe Commerce version, update the `magento/quality-patches` package to the latest version and check the compatibility on the [[!DNL Quality Patches Tool]: Search for patches page](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Use the patch ID as a search keyword to locate the patch.

## Issue

Certain REST API requests enter an infinite loop when the EAV types and attributes cache is disabled.

<u>Prerequisites</u>:

Adobe Commerce [!DNL B2B] extension.

<u>Steps to reproduce</u>:

1. Create a customer account and sign in to the Storefront.
1. Add a product to the cart and open the checkout page.
1. In the browser developer tools, open the Network tab and inspect the REST requests, such as rest/default/V1/carts/mine/estimate-shipping-methods.
1. Disable the EAV types and attributes cache:

   ```
   bin/magento cache:disable eav
   ```

1. Refresh the checkout page and inspect the same REST requests.

<u>Expected results</u>:

1. The checkout REST requests complete without entering an infinite loop.

<u>Actual results</u>:

1. The REST requests fail with HTTP 500 because the infinite loop reaches the PHP call stack size or memory limit.
