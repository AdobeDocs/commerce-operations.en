# AC-18096: Sales GraphQL date fields return an incorrect localized format

The AC-18096 patch fixes the issue where Sales GraphQL date fields return dates in a different format than previous releases by reverting the date format from slash-separated `/` to dash-separated `-`. This patch is available when the [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.83 is installed. The patch ID is AC-18096. Please note that this issue was fixed in Adobe Commerce 2.4.9.

## Affected products and versions

**The patch is created for Adobe Commerce version:**

* Adobe Commerce (all deployment methods) 2.4.9

**Compatible with Adobe Commerce versions:**

* Adobe Commerce (all deployment methods) >2.4.8 <=2.4.9-p1

>[!NOTE]
>
>The patch might become applicable to other versions with new [!DNL Quality Patches Tool] releases. To check if the patch is compatible with your Adobe Commerce version, update the `magento/quality-patches` package to the latest version and check the compatibility on the [[!DNL Quality Patches Tool]: Search for patches page](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Use the patch ID as a search keyword to locate the patch.

## Issue

Sales GraphQL date fields return dates in a different format than previous releases, using slash-separated `/` to dash-separated `-`.

<u>Prerequisites</u>:

- **[!UICONTROL General]** > **[!UICONTROL Locale Options]** > **[!UICONTROL Timezone]**: *Europe/Paris*
- **[!UICONTROL General]** > **[!UICONTROL Locale Options]** > **[!UICONTROL Locale]**: *French (France)*

<u>Steps to reproduce</u>:

1. Create an order.
1. Retrieve order date details using GraphQL:

   ```graphql
   query getOrders {
       customer {
           orders {
               items {
                   orderDateOK: created_at
                   orderDateFAIL: order_date
               }
           }
       }
   }
   ```

<u>Expected results</u>:

- The fields return values in `Y-m-d H:i:s`, matching the output in version 2.4.8.

<u>Actual results</u>:

- The fields return values in `d/m/Y H:i:s`, such as `27/08/2026 14:12:55`, instead of `Y-m-d H:i:s`, such as `2026-08-27 14:12:55`.
