# AC-18128: GraphQL order dates and comment timestamps are incorrect for non-English locales

The AC-18128 patch fixes the issue where order dates and order comment timestamps returned by GraphQL can display incorrect calendar dates in non-English locale settings. This patch is available when the [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.83 is installed. The patch ID is AC-18128. Please note that this issue is scheduled to be fixed in Adobe Commerce 2.4.8.

## Affected products and versions

**The patch is created for Adobe Commerce version:**

* Adobe Commerce (all deployment methods) 2.4.8

**Compatible with Adobe Commerce versions:**

* Adobe Commerce (all deployment methods) >=2.4.8 <2.4.8-p6

>[!NOTE]
>
>The patch might become applicable to other versions with new [!DNL Quality Patches Tool] releases. To check if the patch is compatible with your Adobe Commerce version, update the `magento/quality-patches` package to the latest version and check the compatibility on the [[!DNL Quality Patches Tool]: Search for patches page](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Use the patch ID as a search keyword to locate the patch.

## Issue

Issue where order dates and order comment timestamps returned by GraphQL can display incorrect calendar dates in non-English locale settings.

<u>Steps to reproduce</u>:

1. Navigate to Admin > Stores > Configuration > General > Locale Options. Set Timezone to Europe/Paris. Set Locale to French (France). Save the configuration.
1. Place an order on the Storefront.
1. Execute the following Customer Orders GraphQL query:

   ```
   query getOrders {
       customer {
           orders {
               items {
                   orderDateOK: created_at
                   orderDateFAIL: order_date
               }
           }
       }
   }
   ```

<u>Expected results</u>:

Order date and comment timestamps in GraphQL responses reflect the correct calendar date, regardless of store locale.

<u>Actual results</u>:

For non-en_US locales like fr_FR and de_DE, the order_date was showing the wrong calendar date because of a date parsing issue.
