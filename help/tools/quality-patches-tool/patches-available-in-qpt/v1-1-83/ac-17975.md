# AC-17975: PHP 8.5 compatibility issues affect CLI commands, category editing, Design Configuration, and customer login

The AC-17975 patch fixes the issue where CLI commands, category editing, Design Configuration, and AJAX customer login fail in Adobe Commerce 2.4.9 when PHP 8.5 is used. This patch is available when the [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.83 is installed. The patch ID is AC-17975. Please note that this issue is scheduled to be fixed in Adobe Commerce 2.4.9-p1 and 2.4.10.

## Affected products and versions

**The patch is created for Adobe Commerce version:**

* Adobe Commerce (all deployment methods) 2.4.9

**Compatible with Adobe Commerce versions:**

* Adobe Commerce (all deployment methods) 2.4.9

>[!NOTE]
>
>The patch might become applicable to other versions with new [!DNL Quality Patches Tool] releases. To check if the patch is compatible with your Adobe Commerce version, update the `magento/quality-patches` package to the latest version and check the compatibility on the [[!DNL Quality Patches Tool]: Search for patches page](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Use the patch ID as a search keyword to locate the patch.

## Issue

CLI commands, category editing, Design Configuration, and AJAX customer login fail when Adobe Commerce 2.4.9 runs on PHP 8.5.


<u>Prerequisites</u>:


PHP 8.5 is installed.

 

<u>Steps to reproduce</u>:

1. Run the following CLI command:

   ```
   bin/magento --version
   ```

1. On the storefront, complete a checkout and sign in during checkout while customer CAPTCHA is enabled for login and checkout.
1. In the Admin, open a category when a category attribute has `frontend_input` set to `null`.
1. In the Admin, go to **[!UICONTROL Content]** > **[!UICONTROL Design]** > **[!UICONTROL Configuration]**, then click **[!UICONTROL Edit]** in the **[!UICONTROL Action]** column for a store view.



<u>Expected results</u>:

All operations complete successfully.


<u>Actual results</u>:

The operations fail with errors, such as:

1. ```
   Exception #0 (Exception): Deprecated Functionality: Using null as an array offset is deprecated, use an empty string instead in /var/www/html/vendor/magento/framework/App/Config/ScopeCodeResolver.php on line 62
   ```


1. ```
   report.CRITICAL: Exception: Deprecated Functionality: Using null as the key parameter for array_key_exists() ... in module-captcha/Helper/Data.php on line 92
   ```


1. ```
   There is an error in vendor/magento/framework/Setup/Mvc/MvcApplication.php at line: 170
   Undefined constant "Magento\Framework\Setup\Mvc\GLOB_BRACE"
   ```


1. ```
   Deprecated Functionality: Using null as an array offset is deprecated, use an empty string instead in var/www/html/app/code/Magento/Catalog/Model/Category/DataProvider.php on line 41
   ```
