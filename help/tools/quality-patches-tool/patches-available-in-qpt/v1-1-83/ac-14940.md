# AC-14940: Password reset email isn't sent after a customer's store view is deleted

The AC-14940 patch fixes the issue where clicking [!UICONTROL Reset Password] for a customer account in the Admin does not send the password reset email in some store-related cases. This patch is available when the [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.83 is installed. The patch ID is AC-14940. Please note that this issue is scheduled to be fixed in Adobe Commerce 2.4.9.

## Affected products and versions

**The patch is created for Adobe Commerce version:**

* Adobe Commerce (all deployment methods) 2.4.7 - p10

**Compatible with Adobe Commerce versions:**

* Adobe Commerce (all deployment methods) >= 2.4.4 < 2.4.9

>[!NOTE]
>
>The patch might become applicable to other versions with new [!DNL Quality Patches Tool] releases. To check if the patch is compatible with your Adobe Commerce version, update the `magento/quality-patches` package to the latest version and check the compatibility on the [[!DNL Quality Patches Tool]: Search for patches page](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Use the patch ID as a search keyword to locate the patch.

## Issue

Clicking [!UICONTROL Reset Password] for a customer account in the Admin does not send the password reset email in some store-related cases.

<u>Steps to reproduce</u>:

1. In the Admin, go to **[!UICONTROL Stores]** > **[!UICONTROL Settings]** > **[!UICONTROL All Stores]** and create a secondary store view under the **[!UICONTROL Main Website Store]**.
1. Go to the secondary store view and create a customer account.
1. In the Admin, go to **[!UICONTROL Stores]** > **[!UICONTROL Settings]** > **[!UICONTROL All Stores]** and delete the secondary store view.
1. Go to **[!UICONTROL Customers]** > **[!UICONTROL All Customers]**, find the customer account, and click **[!UICONTROL Edit]**.
1. Click **[!UICONTROL Reset Password]**.

<u>Expected results</u>:

The password reset request completes successfully and the customer receives a password reset email.

<u>Actual results</u>:

An error page displays the message *An error has happened during application run. See exception log for details.* and the password reset email is not sent.
