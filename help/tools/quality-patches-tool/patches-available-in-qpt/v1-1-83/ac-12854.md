# AC-12854: Admin reorder uses the original order number with a `-1` suffix

The AC-12854 patch fixes the issue where reordering an order in the Admin creates a new order number with a `-1` suffix instead of assigning the next sequential order number. This patch is available when the [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.83 is installed. The patch ID is AC-12854. Please note that this issue is scheduled to be fixed in Adobe Commerce 2.4.9.

## Affected products and versions

**The patch is created for Adobe Commerce version:**

* Adobe Commerce (all deployment methods) 2.4.7-p9

**Compatible with Adobe Commerce versions:**

* Adobe Commerce (all deployment methods) >=2.4.7 < 2.4.9

>[!NOTE]
>
>The patch might become applicable to other versions with new [!DNL Quality Patches Tool] releases. To check if the patch is compatible with your Adobe Commerce version, update the `magento/quality-patches` package to the latest version and check the compatibility on the [[!DNL Quality Patches Tool]: Search for patches page](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Use the patch ID as a search keyword to locate the patch.

## Issue

Reordering an order in the Admin creates a new order number with a `-1` suffix instead of assigning the next sequential order number.

<u>Steps to reproduce</u>:

1. Use an existing customer order with reorderable items.
1. In the Admin sidebar, go to **[!UICONTROL Sales]** > **[!UICONTROL Orders]**.
1. Open the order in **[!UICONTROL View]** mode and click **[!UICONTROL Reorder]** in the top button bar.
1. On the **[!UICONTROL Create New Order]** page, complete the required fields and click **[!UICONTROL Submit Order]**.

<u>Expected results</u>:

A new **[!UICONTROL Pending]** order is created with the next unique sequential order number.

<u>Actual results</u>:

The new order gets the original order number with a `-1` suffix instead of the next order number.
