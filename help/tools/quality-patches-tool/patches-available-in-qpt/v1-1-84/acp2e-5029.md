# ACP2E-5029: Catalog price rule changes don't sync to Live Search price feeds

The ACP2E-5029 patch fixes the issue where catalog price rule changes are not sent to [!DNL Live Search] by the regular price feed synchronization, so the new prices appear only after a forced resync. This patch is available when the [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.84 is installed. The patch ID is ACP2E-5029. Please note that this issue is scheduled to be fixed in Adobe Commerce 2.4.10.

## Affected products and versions

**The patch is created for Adobe Commerce version:**

* Adobe Commerce (all deployment methods) 2.4.7-p9

**Compatible with Adobe Commerce versions:**

* Adobe Commerce (all deployment methods) 2.4.7 - 2.4.9

>[!NOTE]
>
>The patch might become applicable to other versions with new [!DNL Quality Patches Tool] releases. To check if the patch is compatible with your Adobe Commerce version, update the `magento/quality-patches` package to the latest version and check the compatibility on the [[!DNL Quality Patches Tool]: Search for patches page](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Use the patch ID as a search keyword to locate the patch.

## Issue

Issue where catalog price rule changes are not sent to [!DNL Live Search] by the regular price feed synchronization, so the new prices appear only after a forced resync.

<u>Prerequisites</u>:

[!DNL Live Search] and Content Staging are enabled, and the indexers are set to Update by Schedule.
The issue is intermittent: it occurs when the staging cron group applies the scheduled update while the index cron group is already reindexing.

<u>Steps to reproduce</u>:

1. Make sure the products to be discounted are searchable through [!DNL Live Search].
1. In the Admin, go to Marketing > Promotions > Catalog Price Rule and click Add New Rule. Set Active to No, select the applicable Websites and the NOT LOGGED IN customer group under Customer Groups, and define conditions for the products. Under Actions, set Apply to Apply as percentage of original, enter the Discount Amount, and click Save.
1. On the rule edit page, in the Scheduled Changes section, click Schedule New Update. Select Save as a New Update, enter an Update Name, set the Start Date to a known future time, set Active to Yes under Rule Information, and click Save.
1. After the Start Date, wait for the Catalog Rule Product and Catalog Product Rule indexers to complete, then add one of the products to the cart on the storefront and check that the discounted price is applied.
1. Do not trigger a forced resync. Allow the next regular price feed synchronization in the index cron group to run, and check the "prices" feed entry in var/log/commerce-data-export.log.
1. Search for the affected products in the [!DNL Live Search] storefront and compare the displayed prices with the prices calculated by the active catalog price rule.

<u>Expected results</u>:

1. The regular price feed synchronization detects the catalog price rule changes and reports a nonzero synced count for the affected products.
1. [!DNL Live Search] displays the updated prices without requiring a forced resync.

<u>Actual results</u>:

1. The next regular price feed synchronization in the index cron group processes all products, but reports synced as 0.
1. [!DNL Live Search] continues displaying the old prices until a forced resync runs.
